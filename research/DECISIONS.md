| D-016 | 2026-11-14 | **Forgiving app search (owner request; Proposed).** FR-SEARCH-02 keeps its six tiers and adds: camel-case and letter/digit word boundaries for word prefixes and initials ("tube", "ptm" → an app labelled "PlayTube Music"); the package name in its own tier (150) below every label match: only its last two segments that are not generic (`com`, `android`…) or vendor prefixes (`google`, `samsung`, `sec`…), ≥ 3 chars, and package hits do not count toward the fuzzy gate; results sort by tier first; fuzzy matching with 1 edit at 4–7 chars and 2 edits from 8 chars (OSA distance to a prefix of the label or any label word, label start first) that runs only when the label tiers found fewer than 5 apps and the query contains a letter (lengths in code points). Everything is precomputed at index build. English labels on a non-English system are not matched. Contacts keep FR-SEARCH-06 unchanged. **Amended 2026-11-25 (owner feedback FB-015 and review finding R-002; Proposed):** neighbouring-key slips ("pg" for "ph") get their own tier (250) between initials and substring: substitutions by neighbouring keys only, at the label or a word start, from 2 characters (1 slip up to 4, 2 for 5–9, 3 from 10), under the fuzzy gate, never on package names; QWERTY by default, the layout is an index parameter (QWERTZ and AZERTY defined, not wired). Distances over code points; no forgiving pass for a query longer than every label plus the edit budget. | Owner: "Typing the exact thing is annoying." Proposed design rationale: tiers keep exact/prefix first (T-SEARCH-21), so the extra recall never reorders what already worked; the fuzzy gate bounds the cost and the noise (T-PERF-05 typo set: median 0.18 ms, p95 0.67 ms on the JVM for 500 apps). English labels would need a resource load per app on every catalog change for little gain on a personal phone. Amendment (FB-015: "way more often than not you press the wrong key… 'pg' when searching for phone"): a slip tier below the deliberate tiers T1–T4 keeps what already worked in place, while "pg" for Phone lands above substring and fuzzy noise. Single letters never slip (one key says nothing about which key was meant; "j" would add 8 of 41 labels in the test list). Two-letter slips add 1.6 apps on average and 7 at worst over all 702 one- and two-letter queries of that list, and find their app in 336 of 338 cases. T-PERF-05 is unchanged within noise. A weighted edit distance (neighbour = half an edit) was rejected: two slips in four letters ("bite" → "note") would pass. |
