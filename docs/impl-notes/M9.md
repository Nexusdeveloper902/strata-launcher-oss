## Bug found and fixed
**Release build would have crashed on the first settings read.** R8 (renaming on in `release`, off only in
`benchmark`) renamed the protobuf-lite message fields (`onboardingDone_` → `h`), while the lite runtime looks fields up
by the names stored as strings in `newMessageInfo`; protobuf-javalite ships no consumer rules. The benchmark build hid
it (`-dontobfuscate`). Fixed by the keep rule and by turning renaming off (decision 3); `checkReleaseApk` now fails on
any renamed protobuf-lite field.

## Choices where the spec left room (Proposed)
1. **The Galaxy A56 stands in for RD-1.** ARCHITECTURE §14.1 fixes RD-1 as a Galaxy A51 (4 GB, Android 13, 60 Hz) with
   a fallback of "any 4 GB / Cortex-A73-class / Android 13 / 60 Hz device, substitution recorded". D-011 makes the A56
   the owner's acceptance phone and keeps RD-1 as the performance baseline. The A56 is faster than RD-1 and 120 Hz, so:
   run the budgets on the A56 at 60 Hz (Motion smoothness: Standard), record "A56 substitutes RD-1" in the gate sheet,
   and read a pass as necessary, not sufficient, for RD-1-class phones. **No budget changes.** Owner: accept, or name
   another RD-1. (Decision record to file: D-016.)
2. **Missing RD-2…RD-5.** Where the owner has no such device, the row is a recorded deviation in the gate sheet (with
   the emulator evidence that exists: nightly API 29/33/35/36 runs, the window-size test), decided by the owner per
   row. T-PERF-11 may use the A56 at 120 Hz as a stand-in for RD-2's frame timing. (D-017.)
3. **No renaming in release R8** (`-dontobfuscate`), shrinking and optimisation on. The source is public, so renaming
   hides nothing; it would make the diagnostic log's Strata frames meaningless without a per-release mapping file
   (M8 part 3 keeps `app.strata.` frames readable), it broke protobuf-lite (above), and the benchmark build already ran
   that way. Cost ≈ 66 KB. The mapping file is still produced and attached to the GitHub release. (D-018.)
4. **Budget enforcement only on a physical device.** `BudgetGate` enforces when the hardware is not an emulator, the
   run is not a dry run and `strata.budgets` is not `off`. On CI the benchmarks are correctness checks: one iteration,
   `suppressErrors=EMULATOR`, and every journey fails loudly if a screen is missing (the old benchmarks returned early).
   JVM microbenchmarks stay measurements. **Owner note:** two pre-existing JVM tests from M2/M4 still assert wall-clock
   budgets (`SearchPerformanceTest.tPerf05_rankingLatency500Apps`, `PerformanceTest` T-THEME-44, both with large
   margins on a desktop JVM). They were left as they are; if they ever flake on CI, turn them into report-only
   measurements (the device harness is the gate). (D-019.)
5. **Percentiles over single passes.** `TraceSectionMetric` aggregates per iteration, so a "p95 of ranking passes"
   cannot come from it. `SliceDurationsMetric` reports every `strata.searchRank` / `strata.contactsQuery` /
   `strata.themeParse` slice as a sampled metric; percentiles are nearest-rank (`BudgetMath`).
6. **Frame budgets.** Janky = `frameOverrunMs > 0` (FrameTimingMetric's deadline-based definition, so 60 and 120 Hz
   need no separate threshold). "No frame > 50 ms": a frame is longer than 50 ms when its CPU time is, or when it
   overran and deadline + overrun is (deadline = 1000 / display refresh rate).
7. **T-PERF-01 "via Home intent"**: MAIN + HOME explicitly aimed at the benchmark build's HomeActivity, so the benchmark
   app does not have to be the default home. **T-PERF-02**: Strata goes to the background behind Settings (the
   "fixture app"), the Home intent brings it back, `timeToInitialDisplay` is the "first frame".
8. **T-PERF-06** measures each contact query (`strata.contactsQuery`) for the 50 ms p95 and keeps app ranking within
   T-PERF-05 in the same run ("app results are not delayed by contacts").
9. **T-THEME-44 on the device** uses a built-in file theme (Paper) at cold start: the typical-size budget. There is no
   256 KiB device fixture; the JVM test covers that case. Strata Default is compiled and is not parsed.
10. **Deferred start-up work.** Without device numbers, only the work ARCHITECTURE §10 step 3 already places after the
    first frame moved (purges, the launch-log prune). The reconcile, icon prefetch and widget `startListening` stay in
    `onStart` (they keep FR-LIST-04 and widget updates correct); move them only if a trace shows they cost cold start.
11. **T-REL-01 short run** is on the release-like benchmark build in the benchmark job, not in the `:app` suite: there
    the target is its own process (a crash is reported, not fatal to the test) and its data can be cleared afterwards
    (`pm clear`), so random input cannot leak settings into later tests. `--pct-syskeys 0` keeps end-call/volume keys
    out; Back stays (major navigation).
12. **T-PRIV-01** is proved three ways (no INTERNET; the kernel refuses Strata's UID a TCP/UDP socket with EACCES;
    `/proc/net` has no socket of that UID after the journeys) instead of `tcpdump`, which needs root on an emulator.
13. **T-COMPAT-06** uses `wm density 160` so the 1920×1200 dp end is a 1920×1200 px surface (cheap on swiftshader);
    split screen stays manual.
14. **Nightly** is not a merge gate (scheduled on the mirror's main). It is the T-COMPAT-01/02 matrix of ARCHITECTURE
    §14.3 and the API 34 T-REL-01 environment of TEST_PLAN, and it produces a Baseline Profile artifact (a profile from
    an emulator is valid: it records which code runs, not timings).
15. **No Baseline Profile committed.** It must come from a real run (device or the nightly artifact); a hand-written
    one would be a guess (docs/perf/optimization-pass-1.md §5).
16. **Version** `1.0.0-rc.1` / `versionCode 2` until the gate passes; then `1.0.0`.
17. **Data-safety answers** are prepared although nothing is submitted (D-011). If Strata is ever published, the
    accessibility lock needs the Play declaration or the `nolock` flavour of ARCHITECTURE §17 (U-014).

## Permissions, dependencies, manifest
- **No new permission.** The app manifest is unchanged; `checkPermissions` and the APK-level check agree.
- **New declared dependency (test APK only):** `androidx.benchmark:benchmark-traceprocessor` 1.4.1 in `:benchmark`, the
  Macrobenchmark family (ARCHITECTURE §15 "Macrobenchmark"). It was already on the Macrobenchmark runtime classpath; it
  is declared so the custom `TraceMetric`s compile. `:benchmark` has no `checkDependencies` (test module); the app's
  `releaseRuntimeClasspath` is unchanged, so `checkDependencies` and `checkLicences` pass unchanged.
- `:benchmark` now depends on `:testing:fixtures` (pure Kotlin). New module `:fixtures:zz` (fixture app, never
  shipped, no gates apply: it is not part of Strata).
