its denial, retry and OEM-help paths, the APP_MODE / lost-default banner, the settings "Default home" and "Uninstall
Strata" rows (FR-SET-02), and the PinRequestActivity shell (T-SEC-02). **Part 2** covers app shortcuts in the sheet
(FR-APPS-08 v1), the work-profile section with pause/resume (FR-APPS-09) and the private-space container
(FR-APPS-10, FR-SEARCH-03 private part). Everything here is `Proposed` where `spec/` left room; change it with a
decision if needed.

## Choices where the spec left room (Proposed)
1. **Split.** Part 1 = onboarding, default home, settings rows, pin shell; part 2 = shortcuts, work profile, private
   space (they share the profile/shortcut platform work).
2. **Screens.** Welcome (privacy promise) → Pick favourites → Set as default → Done ("Go to home"); "Step n of 4" on
   each. Back moves one step back; on Welcome it leaves the entry activity, and does nothing on home (INTERACTION_SPEC
   §3: Back leaves onboarding only after the flow ends). "Not now" on the set-default step or on a card ends the flow
   (`onboarding_done` = true) and home shows the APP_MODE banner. A role granted by an attempt moves to Done on its
   own; a role held from the start shows "Strata is your home app" with Continue (T-ONBOARD-09).
3. **Picker.** Shown apps only (hidden apps are not offered), in list order, with a plain case-insensitive label filter
   (not the search index). Picks are stored in pick order on Continue via `FavoritesRepository.add`; existing
   favourites are kept. A 13th pick is refused with a polite live-region note. Step, picks and query live in the
   `SavedStateHandle`.
4. **Silent refusal.** A role request returning `RESULT_CANCELED` in < 2 s (time between launch and result, measured
   with `elapsedRealtime`) is treated as "don't ask again": the settings chain opens at once and every later attempt in
   the process goes there directly. The flag is per process (no settings field exists for it); a new process costs one
   silent bounce at most.
5. **OEM help card** appears after RESULT_OK without the role, after any settings-chain return without the role, and
   when no screen of the chain exists. It is shown once per attempt (dismissed by Not now / Retry; a resume does not
   bring it back). The known-blocking note uses `OemDetector`: Xiaomi/Redmi/POCO and an `OS<major>.<minor>` token with
   major ≥ 2 in `Build.VERSION.INCREMENTAL` or `Build.FINGERPRINT` (heuristic, U-016).
6. **Banner.** One banner for APP_MODE: "Strata is not your default home app…" [Dismiss] [Set as default], or, once
   the role was held earlier in this process, "Strata is no longer your home app." [Dismiss] [Set again]. Never shown
   during onboarding. Dismiss stores `default_home_banner_dismissed_until = now + 24 h` (field 19); the banner is hidden
   while the last role check (every `onResume`) is before that time. The banner's and the settings row's attempts show
   the Denied / OEM cards as dialogs.
7. **Settings rows.** A new "Home app" group at the top of the settings root (FR-SET-01's group list has no place for
   it; T-SET-02 order is M8): "Default home" with the status as summary, "Uninstall Strata" with a one-line hint. Tap
   on "Default home" while Strata is home opens the home settings (to change it).
8. **Uninstall Strata** while Strata is home: guidance dialog ("Choose another home app first" → [Open home settings]);
   the home settings chain is started for a result; on return the role is re-checked and the system uninstall dialog
   (`ACTION_DELETE` for our package) opens only once Strata is no longer home, else the guidance shows again.
9. **PinRequestActivity** (exported, both `CONFIRM_PIN_*` actions, `excludeFromRecents`, `autoRemoveFromRecents`,
   translucent `Theme.Strata.Dialog`, plain `Activity`). A valid request is declined in v1 (no `accept()`, a short
   toast "Strata can't add items to home yet"); anything else finishes in `onCreate` with no UI.
10. **Device tests and the owner's pass.** Tests that need a human in a system dialog are gated by the instrumentation
    argument `strata.manual=true`; on CI they skip. All device tests restore `onboarding_done` and field 19.

## Choices where the spec left room (Proposed)
1. **Work section/filter.** Work apps stay in the A–Z list (FR-LIST-01: all visible profiles, alphabetically) with the
   system-badged icon; a work bar under the list's search field offers an "All / Work" filter (list and index rebuilt
   for work apps) and a "Work apps" switch. The bar exists only while a work profile exists.
2. **Paused rows** stay listed (the catalog reads paused profiles and flags them QUIET; the profiles' state also marks
   them at once), icon at 60 % α with a "Paused" tag (VISUAL_SPEC §6). A tap, a favourite, a search result or a
   shortcut of a paused app opens "Turn on work apps?" → `requestQuietModeEnabled(false)`; the credential prompt is
   the system's. Not default → "Only the default home app can do this…"; API 26–27 → "Turn work apps on or off in
   your phone's settings."
3. **Private container.** At the list end after the sections, before the Settings/Hidden rows: heading "Private space"
   with Lock (unlocked) and Hide; rows while unlocked (or "No apps in private space"); "Private space — Unlock" while
   locked, nothing while locked with the entry point hidden (API 36). Hide sets field 20; Settings › Apps › "Show
   private space" brings it back (API 35+). A hidden container also keeps its apps out of search.
4. **Private apps in search** while unlocked, after the other apps (no usage boost: the log never stores them), tagged
   "Private space" (T-SEARCH-08 "private container style").
5. **Private sheet.** App info and Uninstall stay (system flows); Rename is shown disabled with the reason; favourite,
   hide, icon and reset are absent. Shortcuts are listed as for other apps (memory only).
6. **Never persisted (P-5)**: no snapshot row (existing guard), no override (repository guard + VM guard), no favourite
   (VM guard; the picker and the cap check use shown apps only), no launch-log row (existing guard), no icon in L1/L2,
   no component, user or platform exception text in logs. The catalog's in-memory entries go with the next reload;
   the list drops them at once on the lock broadcast.
7. **Shortcuts.** Manifest shortcuts first, then dynamic, each by rank, at most 5 (Launcher3-like), enabled ones only,
   blank labels dropped. Rows are text only (no shortcut icons in v1). Loaded when the sheet opens and again on every
   resume while it is open (T-LIFE-10). A start failure = "This shortcut was removed by its app" and the row goes.
   Pinned shortcuts stay v1.x (PinRequestActivity declines).
8. **Test fixture.** The test APK gets a launcher activity (`ShortcutFixtureActivity`, label "Strata shortcut
   fixture") with two static shortcuts; it appears in Strata's list during device tests only.

## CI and review fixes (PR #22)
1. **GMD API 34/36, `tOnboard09` (run 41930665678): `StaleObjectException`.** `stepText()` kept the `UiObject2` from
   `findObject` and read its text after compose had replaced the node (the Done click removes the whole layer). The
   test now re-finds the node on every read and click (`StaleObjectException` → find again) and waits for the previous
   step text with `Until.gone(By.res(step).text(before))`, a selector condition that re-resolves itself.
2. **GMD API 34, `tSec02`: 5167 ms > 5000 ms.** The 5 s budget was mine and measured the wrong thing: logcat shows the
   activity DESTROYED 130 ms after the start; the rest was `ActivityScenario.close()` waiting for its own teardown. The
   spec says "finishes immediately. No UI, no state", so the test now observes the activity itself through the
   lifecycle monitor: finishing when `onCreate` returns, never STARTED or RESUMED, then DESTROYED; no wall-clock budget.
3. **Unknown profile type fails closed** (review, MEDIUM): on API 35+ a non-main profile whose launcher user type cannot
   be read is skipped (profiles, catalog, package loads) instead of being taken for WORK; launch failures for it are
   logged like private ones. `ProfileResolver.classify` + `ProfileKindTest`.
4. **Set-default result after recreation** (review, MEDIUM): the screen in flight is kept by the view models
   (`SetDefaultFlow.onLaunching/onResult`, `SettingsViewModel.HomeSettingsLaunched/HomeSettingsResult`), not by the
   activity; one result launcher per activity offers each result to every receiver, which ignores it unless it started
   the screen. Robolectric tests recreate the activity while the screen is open (onboarding and the uninstall path).
5. **PinRequestActivity** (review, LOW-MED): finishes in `onCreate` without reading the intent; the
   `PinItemRequest.isValid` binder call (an attacker's binder on home's main thread) and the toast are gone. §6 needs
   neither: not calling `accept()` is the decline.
6. **"Don't ask again"** (review, LOW): J-01 says "a *second* cancel within 2 s without UI". The first refusal now always
   shows the Denied card; a quick refusal after an earlier one opens settings. Kept the spec's 2 s.
7. **Private data after locking** (review, LOW): sheet shortcut labels are dropped whenever the sheet closes; search's
   transliteration cache is cleared when private apps leave the index; a private app's sheet closes without "app
   removed" when the space locks.
8. **Shortcut SECURITY failure** (review, LOW): re-checks the role and says only the default home can do this; the row
   is not reported as removed.
9. **Profile reads** (review, LOW): every `read()` runs on the platform thread, in order.
10. **Device tests** (review): the dynamic fixture shortcut is removed and a paused work profile resumed in `@Before`
    and `@After`; the private-space test now opens search (T-SEARCH-08 / T-LIFE-09 ≤ 1 s); T-APPS-16 also checks that the
    icon cache gains no file for a private icon.
