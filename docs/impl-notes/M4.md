## Choices where the spec left room
1. **Issue codes.** The spec defines `Issue(path, severity, code, message)` and the C/D/G/T/R letters but no
   codes. `IssueCode` names them; each code carries its severity and policy letter. Unknown enum →
   `UNKNOWN_ENUM` (`fixed`, D); unknown key → `UNKNOWN_KEY` (`warning`); `schemaMinor > 0` → `NEWER_MINOR` (`info`).
2. **"Rejected" for T-CI-09 negatives.** Lenient mode only rejects R cases, so `schemaVersion 2` is rejected and
   the five others load with a non-`info` issue. `ParsedTheme.isStrictlyValid` (= no issue above `info`)
   is the JVM equivalent of strict schema validity; every sample has zero issues.
3. **What the stored tree keeps.** D and C fields keep their original raw value (round-trip guarantee).
   G fixes (`id`, `name`) and T/control-character fixes of top-level `name`/`author`/`description` are written
   into the tree, so a regenerated id is stable once saved. Nested T fixes (`displayName`) affect only rendering.
4. **Rounding.** Non-integral numbers for integer fields round half-to-even; weights round half-to-even to a
   multiple of 100 (`450` → `400`, issue `ROUNDED`), then clamp. `schemaMinor` outside `0..1000` or
   non-integral is D (the table says D, not C). `32.0` counts as an integer (as in JSON Schema).
5. **Graphemes.** Own deterministic subset of UAX #29 (`Graphemes`), not `BreakIterator`, so JVM and Android
   agree. Prepend and Indic conjunct rules are not modelled (counts can only be higher, never lower).
6. **Seed without a valid colour** stays `kind: seed` in the document (preserved), renders as `fixed`, warning `SEED_MISSING`.
7. **Enforcement details (§7.5).** Derived palettes are enforced even when the global switch is off (§5.2 says
   "always"); fixed palettes only when it is on. Roles in `lockedRoles` (derived kinds) and the pure-black
   `background`/`scrim` are never moved. Bisection targets ratio ≥ target + 0.1; if only the target itself is
   reachable the extreme is used. Step 3 (move the background role) runs for the effective background only once
   `backgroundOpacity` reached 1.0, because before that the role does not decide the backdrop. P8 tries both
   black and white and keeps the smaller tone move. Up to 4 passes over the pair order.
8. **HCT.** Implemented from the published CAM16 and CIELAB equations; HCT → sRGB uses a bounded bisection
   (J for tone, then chroma) of the same shape as the older public HCT solver. Tonal spot uses primary chroma 36,
   neutral 6, neutral-variant 8 and the usual Material role tones. No code was copied; if the owner considers the
   solver structure a port, add the Apache-2.0 NOTICE to `licences.json` (THEME_SYSTEM §5.2, ARCHITECTURE §15).
   Greys have CAM16 chroma ≈ 1.8 here (incomplete chromatic adaptation), so `chroma < 1` is not a neutral test.
9. **Strata Default id** `a413ab93-de91-4614-8c5c-cfbe6d79231b` (spec gives none). Never reuse it.
10. **Crash-loop guard.** The §11.2 index has no counter, so `ThemeIndex.applyCrashCount` is added. A start that
    finds `applyInProgress` within 5 min of `applyStartedAt` increments it; at 2 the theme is marked
    `causedProblem`, the active pointer moves to Strata Default and the file is kept. A flag older than 5 min
    restarts the window at count 1. Safe mode (process-level `boot_attempts`) only marks the offender.
    `apply()` clears a previous `causedProblem` mark (explicit user choice).
11. **Lost index.** If the index is missing/corrupt while themes exist, the active pointer is unknown: boot uses
    `lkg.strata-theme.json` (and makes its id active) with the banner, else Strata Default with the banner.
12. **Reconciliation** compares file names only (no hashing at boot, 500-theme budget). Files without an entry
    are parsed: newer major → entry with `needsAppUpdate` (kept, not applicable); otherwise rejected → moved to
    `themes/quarantine/`. A `.bak` from a migration is deleted by `onBootSucceeded()` of the *next* process,
    when the theme file then parses without migration.
13. **Variant for `wallpaper` mode with the global override:** the override wins (§6). `colors.mode` decides only
    under `FOLLOW_THEME`.
14. **System font scale** is not a resolver input: the UI's density already multiplies `typography.scale` by it.
    Effective animation scale = theme × system; 0 when the system scale is 0 or animators are disabled.
15. **JSON details.** Root container is depth 1; the value count includes containers; string length counts
    UTF-16 units after unescaping (keys included); lone surrogates (raw or escaped) are rejected; columns count
    UTF-16 units. Writer keeps number lexemes (`0.70` stays `0.70`); numbers created in code are written
    shortest (`2.0` → `2`).
16. **Built-in presets** are the five sample files; their canonical copy is `spec/sample-themes/`. The APK asset
    copy under `assets/themes/` is not created yet (needs `:core:data` or `:app`); suggest a `Sync` task from
    `spec/sample-themes/` like the one in `:testing:fixtures`, so there is one source.

## Choices where the spec left room
1. **Repository API.** `ThemeRepository` lives in `:core:theme` (pure, features may use it); `StateFlow<ThemeState>` carries a `ThemePair` resolved for both system dark states, so a dark-mode flip re-renders in the same frame without a new resolution.
2. **Index store over DataStore.** The library is synchronous; `DataStoreThemeIndexStore` blocks the serial theme dispatcher (`IO.limitedParallelism(1)`) while DataStore works on its own IO scope. `format_version = 0` (missing file or replaced after corruption) reads as "no index", so the library rebuilds it with the banner.
3. **First-frame wait.** A pre-draw listener cancels drawing until the loaded theme has been composed or 150 ms passed. The first frame "with" a theme is reported after two frame callbacks; boot success is reported 10 s after the first loaded composition; LKG is offered on `onStop` once the current generation rendered ≥ 10 s. Safe mode, fallbacks and themes awaiting their first frame never become LKG.
4. **Platform inputs.** Wallpaper colours, the dynamic scheme and the animator scale are read off main; the repository waits for the first read. The dynamic scheme is re-read on wallpaper-colour changes and on configuration changes; the animator scale on every `onStart`. API 31–33 dynamic roles use the nearest tonal-palette step (light: surface n1-10, high n1-50, highest n1-100, onSurface n1-900, onSurfaceVariant n2-700, primary a1-600, onPrimary a1-0, outlineVariant n2-200; dark: n1-900, n1-800, n1-700, n1-100, n2-200, a1-200, a1-800, n2-700). API 34+ uses the role resources. Contrast enforcement covers the approximation.
5. **Backdrop.** E(W) is drawn once at the home root under all layers; with `wallpaper.show = false` the backdrop is opaque `background` (Strata Default therefore no longer shows the wallpaper; the window keeps `windowShowWallpaper`). The list no longer draws its own scrim; the search layer keeps its translucent scrim over home. Status/nav bar icons follow the mean luminance of E(black)/E(white).
6. **Animation durations.** `ResolvedAnimation.themeDurationScale` (theme factor, 0 when the system turned animations off) drives Compose durations, because Compose already multiplies by the system animator scale.
7. **Theme switch cross-fade (revised after PR #12 review).** Only the backdrop E(W) fades, over 300 ms × the
   theme scale: one `BackdropFade` (state-backed from/to/progress) is read inside `drawBehind`, so a switch costs
   one recomposition for the new tokens plus backdrop redraws, never a recomposition per frame. Content colours
   (text, surfaces, the Material scheme) switch at once. `StrataTheme(themes, crossFade)` snaps until a loaded
   theme has been composed (`ThemeHost`), so the cold-start first frame already draws the theme, not Default.
8. **Banner.** "Your theme couldn't be loaded, so the default theme is shown." with [Details] and Dismiss; safe mode has its own text. [Choose theme] waits for the M5 picker.
9. **Debug theme switch** (debug builds only): home menu → Themes lists Strata Default, the built-ins and stored themes and applies one live.
10. **Last-known-good guard.** `ThemeState.fallback` (boot fallback: LKG, Strata Default after a failure, crash
    guard, safe mode; or a resolution that fell back) blocks `onStableRender`; dismissing the banner does not
    clear it. An explicit `apply()` ends safe mode and the fallback for the theme, so it can become LKG (same
    reasoning as `apply()` clearing `causedProblem`). Widgets in safe mode (M7) still follow the process flag.
11. **Settings-only process.** `SettingsActivity` uses the same `ThemeHost` (first-frame gate, first-frame and
    boot-success reports, LKG on `onStop`), so a start that only opens settings is not counted as failed.
13. **Frame reports without the Compose clock.** `ThemeHost` detects "frame drawn" with two Choreographer callbacks
    and the repository runs the 10 s boot-success timer after the first reported frame. The earlier
    `LaunchedEffect` (`withFrameNanos` ×2, `delay(10 s)`) ran on the Compose test clock; on CI (GMD API 34, run
    41765134195, `tHome09_homePressResetOrder`) the test scheduler resumed it on the instrumentation thread while
    the main thread was measuring: "performMeasureAndLayout called during measure layout". Device tests also clear
    `boot.state` (`DeviceStateRule`), because every test is a short process and the third one would boot in safe mode.
12. **Quarantine collisions** get a numbered suffix (`<name>.1`, …); an earlier quarantined file is never replaced.

## No new permissions or runtime dependencies
`:core:data` now uses `androidx.core` (AtomicFile; allow-listed). The app manifest is unchanged. The `:t45writer` service is declared only in `:core:data`'s androidTest manifest (test APK).
