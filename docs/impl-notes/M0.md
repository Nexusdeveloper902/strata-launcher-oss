# M0 implementation notes (part 1: skeleton, manifest, home shell)

Choices made where `spec/` left room. Each is `Proposed`; change them with a decision if needed.

## Toolchain
| Item | Version | Why |
|---|---|---|
| Gradle wrapper | 9.8.2 | Current stable; AGP 9.5 needs Gradle 9.x |
| AGP | 9.5.0 | Current stable. Kotlin is built into AGP 9, so Android modules do not apply `org.jetbrains.kotlin.android` |
| Kotlin (+ Compose compiler plugin) | 2.4.21 | Current stable |
| Compose BOM | 2026.06.01 (ui 1.11.4, material3 1.4.0) | Newest BOM whose libraries still allow **compileSdk 36**. BOM 2026.08.00+ (ui 1.12), core 1.19 and lifecycle 2.11 declare `minCompileSdk=37` in their AAR metadata |
| core-ktx / activity / lifecycle / datastore | 1.18.0 / 1.13.0 / 2.10.0 / 1.3.0 | Same compileSdk-36 cap |
| Robolectric | 4.17 | Needs `--add-opens java.base/jdk.internal.access` on SDK 36 (set in the convention plugin) |

Lint `GradleDependency`/`NewerVersionAvailable` are disabled because the caps are deliberate. Raising
compileSdk to 37 would lift them, but ARCHITECTURE §17 fixes compileSdk 36.

## Build layout
- Convention plugins in `build-logic/convention`: `strata.android.application`, `strata.android.library`,
  `strata.android.compose`, `strata.jvm.library`. Namespaces are derived from the module path
  (`:core:platform-api` → `app.strata.launcher.core.platformapi`).
- All ARCHITECTURE §2 modules exist except `:benchmark` (added with the CI pipeline in part 2).
  Empty `:feature:*` modules do not apply the compose plugin yet; add it when the feature starts.
- Pure-JVM modules register a `testDebugUnitTest` alias for `test`, so one command runs every unit test.
- Lint: `HardcodedText`, `SetTextI18n`, `PluralsCandidate` are errors (T-CI-04). The custom
  `StringConcatInUi` rule is part 2.
- No `lock` flavour dimension yet (ARCHITECTURE §17): the lock service is not in M0, and flavours would
  rename every variant task (`testDebugUnitTest` → `testFullDebugUnitTest`). Add it with the lock service
  (D-011 includes the lock in the personal build, so a single variant may be enough).
- Build type `benchmark` is not defined yet (part 2, with `:benchmark`).

## Interfaces and state
- `onboarding_done` (temporary store): interface `OnboardingStore` in `:core:platform-api`
  (`…platformapi.settings`), DataStore implementation `DataStoreOnboardingStore` in `:core:data`
  (`filesDir/datastore/entry_flags.bin`, 2-byte format, corruption → default). It is in platform-api, not
  `:core:data`, so `:testing:fakes` stays pure JVM (ARCHITECTURE §2.1 note: platform-api hosts every
  service interface features call). **M1:** migrate the value into `settings.pb` field 3, delete the file,
  replace `OnboardingStore` with `SettingsRepository`.
  `datastore-core` is used with a hand-written serializer instead of protobuf, to avoid adding the protobuf
  plugin before M1 needs it.
- `RoleController` matches ARCHITECTURE §3. `SystemIntent` is a framework-free sealed type
  (`RequestHomeRole`, `HomeSettings`, `DefaultAppsSettings`, `Settings`); `SystemIntentFactory` in
  `:platform:system` maps it to an `Intent`.
- `Clock` in `:core:common` is `nowMillis(): Long` only; the minute `ticks` flow arrives with the header (M3).
- HomePressed → `HomeEffect.ReturnToRest` effect (logged only in M0; layers arrive in M2/M3).

## Behaviour details
- The debug-only "Set as default" button lives inside the APP_MODE banner. Release builds show the banner
  text without the button until M6.
- Role request result: a non-OK result within 2 s is treated as a silent refusal ("don't ask again") and opens
  the settings fallback chain (ANDROID_PLATFORM §2, T-ONBOARD-05 groundwork). A slower cancel only re-checks.
- `SettingsActivity` reads the flag asynchronously and renders nothing until it is known (no disk on main).
  Any start that is not `MAIN`+`LAUNCHER` (including `APPLICATION_PREFERENCES`) opens the settings root stub.
- StrictMode (debug): thread `detectAll` + `penaltyDeath`; VM leaked closables, content URI without
  permission, unsafe intent launch (31+). Skipped under Robolectric.
- Uncaught exceptions: app-scope `CoroutineExceptionHandler` logs and never rethrows; a default
  thread handler logs and then delegates to the previous handler (the platform crash still happens).
- Logger: `RingLogger` (2 000 entries) → `RotatingFileLogSink` (`noBackupFilesDir/logs/strata-{0,1}.log`,
  2 × 256 KiB, written on its own thread) + logcat (debug: all, release: WARN+).

## Manifest
- M0 declares only `HomeActivity` and `SettingsActivity`; the other §22 components arrive with their
  milestones (lint fails on manifest entries without classes). `<queries>` is complete already.
- Backup rule files carry the full include set of ANDROID_PLATFORM §17. The explicit `<exclude>` entries
  (`themes/images/` for cloud, `restore/`, `launch_log.db`) are omitted: they are not under any include,
  so they are already excluded, and lint flags excludes outside an include.
- Merged manifest also contains `app.strata.launcher.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`
  (declared and used by androidx.core for `ContextCompat.registerReceiver` on API < 33). It is the app's own
  signature permission, not a system one; **part 2's `checkPermissions` should ignore it** rather than
  stripping it. `config/approved-permissions.txt` lists the three §23 permissions.

## Local environment (not committed)
Maven Central rate-limits this sandbox (HTTP 429). `~/.gradle/init.d/central-mirror.gradle` rewrites
Maven Central to Google's mirror, and `~/.gradle/gradle.properties` sets
`strata.robolectric.repoUrl` (read by the convention plugin) so Robolectric downloads its SDK jars there too.
