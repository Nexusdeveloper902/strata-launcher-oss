Choices made where `spec/` left room. Each is `Proposed`; change them with a decision if needed.

| Item | Version | Why |
|---|---|---|
| Gradle wrapper | 9.8.2 | Current stable; AGP 9.5 needs Gradle 9.x |
| AGP | 9.5.0 | Current stable. Kotlin is built into AGP 9, so Android modules do not apply `org.jetbrains.kotlin.android` |

Lint `GradleDependency`/`NewerVersionAvailable` are disabled because the caps are deliberate. Raising
compileSdk to 37 would lift them, but ARCHITECTURE §17 fixes compileSdk 36.

## Build layout
- Convention plugins in `build-logic/convention`: `strata.android.application`, `strata.android.library`,
  `strata.android.compose`, `strata.jvm.library`. Namespaces are derived from the module path
  (`:core:platform-api` → `app.strata.launcher.core.platformapi`).
- All ARCHITECTURE §2 modules exist, including `:benchmark` and `:lint-rules` (part 2).
  Empty `:feature:*` modules do not apply the compose plugin yet; add it when the feature starts.
- Pure-JVM modules register a `testDebugUnitTest` alias for `test`, so one command runs every unit test.
- Lint: `HardcodedText`, `SetTextI18n`, `PluralsCandidate` are errors (T-CI-04). The custom
  `StringConcatInUi` rule lives in `:lint-rules` (part 2).
- No `lock` flavour dimension yet (ARCHITECTURE §17): the lock service is not in M0, and flavours would
  rename every variant task (`testDebugUnitTest` → `testFullDebugUnitTest`). Add it with the lock service
  (D-011 includes the lock in the personal build, so a single variant may be enough).
- Build type `benchmark` exists in `:app` (part 2).

## Interfaces and state
- `onboarding_done` (temporary store): interface `OnboardingStore` in `:core:platform-api`
  (`…platformapi.settings`), DataStore implementation `DataStoreOnboardingStore` in `:core:data`
  (`filesDir/datastore/entry_flags.bin`, 2-byte format, corruption → default). It is in platform-api, not
  `:core:data`, so `:testing:fakes` stays pure JVM (ARCHITECTURE §2.1 note: platform-api hosts every
  service interface features call). **M1:** migrate the value into `settings.pb` field 3, delete the file,
  replace `OnboardingStore` with `SettingsRepository`.
  `datastore-core` is used with a hand-written serializer instead of protobuf, to avoid adding the protobuf
  plugin before M1 needs it.
- `RoleController` matches ARCHITECTURE §3. `SystemIntent` is a framework-free sealed type
  (`RequestHomeRole`, `HomeSettings`, `DefaultAppsSettings`, `Settings`); `SystemIntentFactory` in
  `:platform:system` maps it to an `Intent`.
- `Clock` in `:core:common` is `nowMillis(): Long` only; the minute `ticks` flow arrives with the header (M3).
- HomePressed → `HomeEffect.ReturnToRest` effect (logged only in M0; layers arrive in M2/M3).

## Behaviour details
- The debug-only "Set as default" button lives inside the APP_MODE banner. Release builds show the banner
  text without the button until M6.
- Role request result: a non-OK result within 2 s is treated as a silent refusal ("don't ask again") and opens
  the settings fallback chain (ANDROID_PLATFORM §2, T-ONBOARD-05 groundwork). A slower cancel only re-checks.
- `SettingsActivity` reads the flag asynchronously and renders nothing until it is known (no disk on main).
  Any start that is not `MAIN`+`LAUNCHER` (including `APPLICATION_PREFERENCES`) opens the settings root stub.
- StrictMode (debug): thread `detectAll` + `penaltyDeath`; VM leaked closables, content URI without
  permission, unsafe intent launch (31+). Skipped under Robolectric.
- Uncaught exceptions: app-scope `CoroutineExceptionHandler` logs and never rethrows; a default
  thread handler logs and then delegates to the previous handler (the platform crash still happens).
- Logger: `RingLogger` (2 000 entries) → `RotatingFileLogSink` (`noBackupFilesDir/logs/strata-{0,1}.log`,
  2 × 256 KiB, written on its own thread) + logcat (debug: all, release: WARN+).

## Manifest
- M0 declares only `HomeActivity` and `SettingsActivity`; the other §22 components arrive with their
  milestones (lint fails on manifest entries without classes). `<queries>` is complete already.
- Backup rule files carry the full include set of ANDROID_PLATFORM §17. The explicit `<exclude>` entries
  (`themes/images/` for cloud, `restore/`, `launch_log.db`) are omitted: they are not under any include,
  so they are already excluded, and lint flags excludes outside an include.
- Merged manifest also contains `app.strata.launcher.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`
  (declared and used by androidx.core for `ContextCompat.registerReceiver` on API < 33). It is the app's own
  signature permission, not a system one; `checkPermissions` ignores exactly
  `<applicationId>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (and any other custom `<permission>` fails). `config/approved-permissions.txt` lists the three §23 permissions.

## Local environment (not committed)
Maven Central rate-limits this sandbox (HTTP 429). `~/.gradle/init.d/central-mirror.gradle` rewrites
Maven Central to Google's mirror, and `~/.gradle/gradle.properties` sets
`strata.robolectric.repoUrl` (read by the convention plugin) so Robolectric downloads its SDK jars there too.

## Part 2: CI gates, ktlint, benchmark, Gradle Managed Devices
Gate logic is pure Kotlin in `build-logic/convention` (`GateLogic.kt`) with JUnit negative cases per gate
(`./gradlew :build-logic:convention:test`, 16 tests). Task wrappers are in `GateTasks.kt`, wiring in
`GateRegistration.kt` and `RootGatesConventionPlugin.kt` (`strata.gates`, applied to the root).

| Gate | Task | Test IDs | Input and rule |
|---|---|---|---|
| Permissions | `:app:checkPermissions` | T-CI-01, T-PRIV-03 | Merged **release** manifest `uses-permission*` equals `config/approved-permissions.txt`; the named forbidden set (INTERNET, AD_ID, QUERY_ALL_PACKAGES, ...) gets its own message |
| Dependencies | `checkDependencies` (every module) | T-CI-02, T-PRIV-02 | `releaseRuntimeClasspath` (JVM: `runtimeClasspath`) resolved modules vs `config/dependency-allowlist.txt`, after `config/forbidden-dependencies.txt` (OkHttp, Retrofit, Ktor, Firebase, Play services, billing, analytics, ...). Lists accept `group:name`, `group:*`, `prefix.*` |
| Module graph | `checkModuleGraph` (every module) | T-CI-03 | ARCHITECTURE §2.1 table over non-test configurations, plus "pure modules apply no Android plugin" and "common/model/json use only stdlib and coroutines-core". `:testing:*` may also use other `:testing:*` (fixtures on fakes) |
| Entitlements | `checkEntitlements` (root) | T-CI-08 | `isPro`, `premium`, `entitle`, `purchase`, `billing` in `src/main` text sources, `spec/theme.schema.json`, `spec/sample-themes`, `assets/themes`. `build-logic` itself is excluded |
| ktlint | `ktlintCheck` / `ktlintFormat` | - | ktlint CLI 1.8.0 run from a build-only configuration (version in the catalog); rules in `.editorconfig` (ktlint_official, 120 columns, `function-signature` and `class-signature` off) |

Notes and limits:
- `checkDependencies` allows all of `androidx.*` because the §15 list is by family and AndroidX pulls many
  transitive artifacts. Okio is allowed explicitly (DataStore). Anything else needs an entry.
- The allow-list gate does **not** do the T-PRIV-02 "APK class scan" nor T-PRIV-03's `aapt dump permissions` on
  the release APK; manifest and classpath checks stand in for them. Add an APK step when release signing exists.
- `StringConcatInUi` (`:lint-rules`, lint 32.5.0 = AGP 9.5.0 + 23): flags `+`/templates that contain
  `getString`/`stringResource`/... calls or feed `Text`, `setText`, `Toast.makeText`, `setContentDescription`...
  Wired into every Android module as `lintChecks`. Four lint-test cases.
- `:benchmark` (`strata.android.benchmark`, `com.android.test`): empty cold-start `StartupBenchmark`. `:app` has a
  `benchmark` build type (release-like, debug-signed, `profileable` via `src/benchmark/AndroidManifest.xml`).
  Run on a device with `./gradlew :benchmark:connectedBenchmarkAndroidTest`. Not run here.
- Managed devices `api26` (google), `api34` (google; ATD has no soft keyboard, so T-SEARCH-10 cannot run there), `api36` (google; no ATD image assumed for 36), all
  Pixel 6 x86_64, with the AndroidX Test Orchestrator. Task: `:app:api34DebugAndroidTest`. The
  smoke test is `app/src/androidTest/.../HomeSmokeTest.kt` (clicks through onboarding if shown, then the
  placeholder). **Never run here** (no emulator, no KVM); compiled only (`assembleDebugAndroidTest`).
- ARCHITECTURE §14.3 lists API 26 as `google_apis`, 34 as ATD where available: matches the above.
- CI: `.github/workflows/ci.yml`, jobs `build`, `unit`, `lint`, `ktlint`, `static-gates`, `gmd-smoke` (26/34/36).
  `tools/ci/run-gmd.sh` retries a managed-device task once and only when the log shows an infrastructure failure
  (emulator boot, adb, system image download); test failures are never retried. The workflow has not run on
  GitHub yet. Action versions are pinned to majors (checkout/setup-java/upload-artifact/cache v4,
  setup-gradle v4, setup-android v3). The debug APK is uploaded as `strata-debug-apk`.
- `lock` flavour dimension: left out again (see above); the personal build keeps a single variant.
- Local verification command: `./gradlew assembleDebug testDebugUnitTest lintDebug ktlintCheck checkPermissions
  checkDependencies checkModuleGraph checkEntitlements assembleDebugAndroidTest :benchmark:assemble
  :build-logic:convention:test`.
