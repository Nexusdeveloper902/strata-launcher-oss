## Choices where the spec left room (Proposed)
1. **Split.** Part 1 = theme files; part 2 = icons + editor (see top).
2. **Zip reading in memory.** The archive (≤ 24 MiB) is read into memory and parsed from its central directory, so
   entries with data descriptors work; no entry is ever extracted to a path. The only temp files are the font copies
   for `Typeface.Builder`, in `cacheDir/import/<random>/font.<ext>`, deleted in `finally` (§10.3.3 "extraction").
3. **Messages for bundle problems.** Zip bomb, too many entries and oversize → "The file is too large."; unexpected or
   unlisted entries and unlisted references → "unexpected files"; hash/size mismatch, broken structure → "damaged";
   encrypted, ZIP64, other methods and a bad manifest → "This file isn't a Strata theme."; `bundleVersion > 1` → the
   newer-version text. Images get a new message "The wallpaper in this bundle couldn't be read." (§8.2 has none).
4. **WebP metadata.** The platform encoder embeds an sRGB ICC chunk. After re-encoding, `ICCP`/`EXIF`/`XMP ` chunks are
   stripped (and their `VP8X` flags cleared), so the stored file is "already stripped WebP" and a re-import keeps the
   bytes (T-THEME-28). A clean WebP is still fully decoded once before it is kept as is.
5. **"Identical"** (§10.4) compares the canonical writer output without `createdAt`/`modifiedAt`, so an exported copy
   (export refreshes `modifiedAt`) counts as identical.
6. **Replace undo** keeps the old bytes in memory until the process ends ("until next start"); the import screen
   offers Undo after a Replace.
7. **Delete undo.** The active theme switches to last-known-good (or Strata Default) at once; the file and entry go
   after 5 s on the app scope, so leaving the screen still commits. Undo re-applies a theme that was active. A delete
   pending when the process dies is simply not done.
8. **Hiding.** Built-in presets can be hidden (index entry with origin `BUILTIN`, `hidden = true`); Strata Default is
   never hidden or deleted (it is the recovery target).
9. **Names.** Copies are "Name (copy)", then "Name (copy) (2)"… Collisions compare case-insensitively against every
   library name, built-ins included; numbered names keep within 64 UTF-16 units.
10. **Bundles** include only fonts the theme uses; unused bundle fonts are not stored. Fonts and images are written
    only if absent (content-addressed) and garbage-collected on delete and replace (kept while any entry needs an app
    update).
11. **Share** sends the JSON document (most receivers understand it); bundles go through Export. Each share copy has
    its own random directory under `cacheDir/share/`, so the receiver sees the suggested name.
12. **Purge.** At the first `startTheme()` of a process, copies whose newest file is ≥ 24 h old are deleted. A copy
    handed out by a previous process stays readable for 24 h.
13. **ATTACH_DATA** is started directly, not in a chooser, so "no handler" can be detected; the system resolver
    still lets the user pick when several apps qualify.
14. **Import summary contrast** is computed with enforcement off (it describes the theme's own colours) and the
    worse of the light and dark resolution; the preview thumbnail uses the theme as it will render.
15. **Missing icon pack** in the summary is left empty until pack discovery (part 2).
16. **Platform media in `:core:data`.** `ThemeMedia` is a pure interface in `:core:theme`; its Android implementation
    lives in `:core:data` (Android SDK only, like `AtomicFile`), not in `:platform:*`, because `:core:data` cannot
    depend on platform modules and the repository owns the import.
17. **Themes screen** is its own non-exported `ThemesActivity` (settings task affinity), started from the home menu.

## Review fixes (PR #15)
1. **Replace + Undo keeps its media.** The replaced version is held by `ThemeLibrary` (latest one per id, until the
   process ends) and its fonts/images count as referenced by garbage collection; `restore(id)` collects only after the
   old version is back. An edit (`save`) or delete of the id drops the pending undo.
2. **Undo after a second Replace** restores the version just replaced (the latest, not the oldest).
3. **Delete window.** `DeleteTicket` carries the file hash; `commitDelete` deletes nothing when the theme was
   re-imported/replaced (hash changed) or applied again inside the window. `undoDelete` re-applies only while the active
   theme is still the one the delete switched to. The library view model serialises deletes and undo with a mutex
   (the second delete commits the first in the same critical section); the 5 s commit claims its ticket under the lock
   and then runs non-cancellable, so an Undo after that point shows "Too late to undo".
4. **Non-I/O failures** in import commit, undo of Replace, duplicate, copy-for-edit and delete are caught and mapped to
   an error; `OutOfMemoryError` while preparing an import becomes "too large".
5. **Prepared imports** are dropped when the preparing coroutine is cancelled, and at most 4 are kept (oldest dropped).
6. **Media of prepared imports** is pinned against garbage collection until commit or discard (`pinnedMedia`).
7. **EXIF orientation** (framework `android.media.ExifInterface`, API 24; no new dependency) is applied to the pixels
   before re-encoding.
8. **As-is WebP** only when clean: no chunk outside `VP8 `/`VP8L`/`VP8X`/`ALPH`, no metadata `VP8X` flags, no bytes
   after the RIFF payload; anything else is re-encoded.
9. **Unreferenced bundle images** are not stored.
10. **Export failures** are reported: a create-document result without prepared bytes (process recreated) and a missing
    document provider show "The theme couldn't be exported."
11. **Bundle export** that would break the import limits (§10.3.3: 24 MiB total, 4 fonts, archive size) fails with
    "With its fonts and wallpaper this theme is too large to import again. Export the theme only."
12. **Zip directory entries** (`zip -r` output) are ignored for the 8-entry limit, as §10.3.1 says they are ignored; the
    central directory is still capped at 32 entries.
13. **Stale `cacheDir/import/` dirs** (older than 1 h, left by a process killed mid-check) are purged at start.
14. Kept: `AndroidDocumentIO.write` opens with `"wt"`. The target is the empty document just created by
    `ACTION_CREATE_DOCUMENT`, and truncation is what prevents stale trailing bytes when a provider reuses a document;
    `"w"` does not truncate on every provider.

## Choices where the spec left room (Proposed)
1. **PACK_OK fixture.** The test APK is the pack: its androidTest manifest declares an exported activity with the ADW
   THEMES action, `assets/appfilter.xml` and two solid-colour drawables. No separate fixture APK module (`:testing:*`
   must be pure JVM, and GMD cannot install extra APKs); uninstall flows are covered at level R and in the manual pass.
2. **Parser limits.** "Items" = every element (any tag); depth counts from the root element (≤ 8); wall-time limit 2 s,
   checked every 256 events; attribute values ≤ 512 chars, ≤ 16 attributes read per element. Text files are decoded as
   UTF-8 by us and refused if they contain `<!DOCTYPE`, `<!ENTITY`, `<!ELEMENT` or `<!ATTLIST`; compiled `res/xml/`
   files are bounded by their compiled size. Lookup order: `res/xml/appfilter`, `res/raw/appfilter`, `assets/appfilter.xml`.
   Drawable names must match `[A-Za-z0-9_]{1,128}`; components are validated and `.Class` is expanded.
3. **Fallback tags** (`iconback`/`iconmask`/`iconupon`/`scale`) are parsed and ignored: the theme's `pack.fallback`
   decides what unmapped apps show. Calendar entries use `prefix` + day of month; the day is in the cache key.
4. **Unusable packs** are listed (`usable = false`), excluded from `installedIconPacks`, and a theme that uses one gets
   its own notice: "…which can't be read. System icons are shown instead." (with the store button, for an update).
5. **Notice "once per apply"** is per apply generation and per process; Dismiss and the store button both end it.
   A pack that is uninstalled while its theme is active shows the notice (unless already dismissed in that apply).
6. **Per-app overrides from a removed pack** are kept (the pack may come back) and fall back to the theme icon; a
   one-time notice per pack and process names the package.
7. **Rendering.** Adaptive layers are drawn at 1.5× the icon and masked with an anti-aliased path (`SRC_IN`), not
   `clipPath`. `system` shape uses the platform mask (drawing the `AdaptiveIconDrawable`). Legacy icons with the plate
   are wrapped into an `AdaptiveIconDrawable(surface, InsetDrawable(icon, 26.67 %))`. Monochrome = the layer tinted
   `SRC_IN` on a `surface` plate. Desaturated = Rec. 709 luminance × tint colour. Work badges are applied after
   rendering (`getUserBadgedIcon`). Pack/override drawables are never masked or tinted.
8. **Cache.** Key = request fields + pack version/parse state + override + calendar day + API level + glyph bundle
   version (`none` until M8). Old L2 entries age out through the 32 MB LRU instead of being deleted on a theme change.
9. **Pack discovery** publishes the installed list before parsing (pending packs count as usable), so the first frame
   does not wait for a 2 MiB parse; icons rendered meanwhile have a "pending" key and are re-requested afterwards.
10. **Chooser.** Lists `res/xml/drawable.xml` when present, else the distinct appfilter drawables (≤ 20 000; the grid
    shows ≤ 2 000, search narrows). Gallery images are not offered (FR-APPS-06).
11. **Package events.** A context-registered receiver (`RECEIVER_NOT_EXPORTED`, system broadcasts only) for package
    added/removed/replaced/changed refreshes packs; `onStart` refreshes too.

## Review fixes (PR #18)
1. **Compiled `res/xml` references.** In a compiled appfilter, `drawable="@drawable/x"` reads back as `@<id>`. The parser
   now resolves references (`getAttributeResourceValue` + `getResourceEntryName`, errors skip the item), and also
   accepts `@drawable/x` in text files; the name pattern applies after resolution. The device fixture pack now ships a
   compiled `res/xml/appfilter.xml` with `@drawable/` references (CI covers the path); `PackXmlReader` (lookup order,
   bounds) is unit-tested over a fake `PackResources`.
2. **Chooser initial pack** is chosen once both the app (with its override) and the discovered packs are known.
3. **Cache race.** A render whose cache key changed meanwhile (pack parsed/removed) is returned but not cached; the L2
   write moved after that check.
4. **Pack updates.** `PACKAGE_REMOVED` with `EXTRA_REPLACING` is ignored (no transient "missing" notice). A failed
   discovery (`discover()` = null) keeps the last list; before the first success an empty discovered list is published
   so theme inputs do not wait forever.
5. **Pack bitmaps** (`.png/.webp/.jpg`) over 1024 px on a side are skipped after an `inJustDecodeBounds` check (Proposed
   limit; icons are drawn at ≤ 512 px). The OOM catch stays.
6. **`AppIcon`** clears the previous bitmap when a new request yields the monogram.

## Choices where the spec left room (Proposed)
1. **Edit the raw tree, not the typed document.** Every edit is a path set/remove on the stored tree, re-validated with
   the import parser; unknown keys, `x-*` members and preserved originals survive editing (FR-THEME-19). The session's
   id is fixed: a JSON text naming another id is applied with the session's id ("The theme kept its own id").
2. **Undo** keeps 200 snapshots (≥ 100). A coalescing run (slider drag, one text-field edit session, the HCT sliders of
   one colour) opens only with a real change and closes on release/focus loss; a drag that ends where it started is no
   step. Undo, redo, Fix, a theme reset, an image seed and an applied JSON text are each one step.
3. **Resets.** Field: the member is removed (renders the schema default). Group: every schema-defined member of the
   group is removed, unknown/`x-*` members of the group kept; "About" resets author and description (the name is
   required and has no reset). Theme: "Reset to *basedOn* preset" (when the preset still loads) or "Reset to Strata
   Default"; id, name, `basedOn`, timestamps, author and description are kept.
4. **Built-ins open as an unsaved copy** ("Name (copy)", new id, `basedOn`); nothing is written until Save, so opening
   and leaving a built-in leaves the library unchanged. "New theme" starts from Strata Default's values.
5. **Drafts.** `themes/drafts/<sessionId>.json` = `{"draftVersion":1,"sessionId","sourceId","isNew","savedAt","theme"}`
   (limits = theme limits + 8 KiB / +1 depth). The 2 s timer writes only when the tree changed since the last write and
   removes the draft when the session is clean again; `onStop` writes at once. Save and Discard delete it. A stored
   theme's draft is *offered* in a modal dialog when its editor opens (Restore / Discard); until it is answered no edit,
   save or autosave happens, and Back leaves without deleting it. A never-saved session's draft (copy, new theme)
   is restored without asking after the activity is recreated, and listed in the library ("Unsaved changes to …",
   Continue editing / Discard). Unreadable drafts are deleted. The JSON view's unapplied text is not part of the draft.
6. **Preview.** Built in `:feature:theme` from the shared `:core:ui` pieces (`AppRow`, `SearchPillFrame`, `strataBackdrop`,
   the theme typography) because a feature must not import `:feature:home`; clock/date/favourites/index are drawn from
   the same resolved tokens. Light/dark is forced per preview toggle (appearance override), so both palettes can be
   edited whatever the theme's mode. The preview renders the theme's **own** colours (enforcement off for fixed
   palettes; derived palettes are still enforced, §5.2), so an edit is always visible; the banner says enforcement
   adjusts them on the home screen. The wallpaper toggle draws a stand-in gradient of the current wallpaper colours
   (black when off), since the wallpaper bitmap is never read (P-7). "Your apps" are the first 12 list labels; "Sample
   apps" uses a fixed list.
7. **Contrast in the editor** is the §7.3 static check (any wallpaper) for every case the theme can show: each variant
   of its mode, and dark with pure black toggled on. Chips show the worst pair the role takes part in (`background`
   and `scrim` share P1–P3 through the effective background; `divider` has none). Banner lines are the failing pairs in
   words, per variant. The status line is a polite live region whose text changes only when the problem set changes.
   "Show me" turns on the problem overlay (black-and-white outline + "Hard to read" label, never colour alone) and
   scrolls to the preview.
8. **Fix** runs the §7.5 enforcer on each failing case and writes only the moved roles into `colors.light`/`colors.dark`
   and any raised `dim`/`backgroundOpacity` (rounded up to 2 decimals) into `wallpaper`; up to 8 rounds, re-evaluating
   after each case. Known limit: it is the render-time enforcer, so a contrived palette where the enforcer itself does
   not converge (seen with a neutral grey accent over a shown wallpaper at dim 0.1) may stay failing; the banner then
   stays up.
9. **Create from image.** `PickVisualMedia` (images only); no storage permission, no `<queries>`, no GMS picker module
   declared (on devices without the system picker the contract falls back to the document picker). The picked
   `content:` URI is read through `DocumentIO` (≤ 16 MiB), sniffed and bounds-checked (§10.3.3), decoded sampled to
   ≤ 128 px, off the library's serial dispatcher. Photos are read up to 48 MiB and sampled whatever their pixel
   count (a 50 MP camera image works); only keeping the image as the wallpaper is bound by the §10.3.3 limits ("too
   large to keep as the wallpaper" otherwise). A picker result that arrives before the session exists (process death
   while the picker was open) is kept in the saved state and applied once the session opens. Seed: own method (5-bit bins → HCT, chromatic mid-tone bins vote for 10° hue sectors weighted by count ×
   chroma, neighbours half; strongest bin of the winning sector; greys → most common colour). The tree gets
   `source.kind = seed`, `seedColor`, and enforced tonal-spot palettes for both variants (pure black included) as the
   fixed fallback. "Also use the image as this theme's wallpaper" (off by default) stores it as stripped WebP in the
   image store and sets `wallpaper.image`; it is pinned against garbage collection for the process and referenced by
   the draft until saved. "Create from image" in the library opens the picker once; cancelling closes the empty
   session. "Colours from image…" is also in the editor's Colours group.
10. **Save / Apply.** Save writes through `ThemeLibrary.save` (an active theme re-renders at once). Apply saves and
    applies and stays in the editor. Back with changes asks Save / Discard / Keep editing.
11. **Not in the editor (yet):** fonts (font manager and bundled OFL catalogue are open, TQ-1), icon pack, locked roles
    and the wallpaper image reference other than through create-from-image; all are editable in the JSON view.
12. **Apply trace.** `strata.themeApply` begins on the tap (library row or editor Apply) and ends in the first
    Choreographer callback after the composition of the new apply generation, i.e. once the frame drawing it is done.

## CI and review fixes (PR #21)
1. **Theme leak between device tests (run 41893533129, API 26/34/36).** `ThemeEditorDeviceTest.tTheme51…` applied its
   theme and left it active; the next process booted with it and `ThemeFilesDeviceTest.tTheme27…` (which read the
   active id before the repository had booted, i.e. the Strata Default placeholder) saw it after. The editor tests now
   restore the previously active theme and delete their themes and drafts in `@After`; `tTheme27…` waits for the booted
   state before reading the active id.
2. **`Detected multithreaded access to SnapshotStateObserver` (API 34, `tHome10`).** The theme repository wrote `state`
   from a `Default` worker; `ThemeHost` collects it directly in composition, and under the Compose test clock the
   collector resumed inline on that worker and ran the recomposition there. The code path predates this branch (main
   passed by timing). The repository now publishes `state` on a `publishDispatcher` (the main dispatcher in the app;
   unconfined in JVM tests).
3. Review: modal draft offer (never deleted or overwritten while unanswered); picker result kept across process death;
   draft delete always runs and is serialised with the autosave (no orphan rows); a save records the written snapshot,
   so edits typed during it stay dirty; control values (`effective`) are computed on the main thread with each edit
   (only preview and contrast are off-thread); Fix and image results are dropped when the session changed meanwhile;
   image seed decode outside the library lock and without the wallpaper pixel limit; the name cannot be emptied; the
   JSON view announces only valid ↔ invalid; stricter tests (one undo removes the drag; `tTheme51` also forbids disk
   access on the main thread) and benchmarks that fail on a missing node.
