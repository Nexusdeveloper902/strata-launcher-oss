## Choices where the spec left room (Proposed)
1. **Split.** Part 1 = settings graph + icons; part 2 = backup/restore; part 3 = a11y/i18n hardening and the
   diagnostic log export.
2. **Root groups.** "Default home" and "Uninstall Strata" (FR-SET-02) lead the **Home** group (T-SET-02 lists no
   separate group for them). The old "Privacy" group is now **Privacy & permissions**: a "Permissions and access" row
   (the FR-SET-03 page) plus the app-history controls. **Themes** has one row (the theme library); **About** one row
   (version in the summary). Backup is added in part 2 between Apps and Privacy & permissions.
3. **`coverage` signature.** ARCHITECTURE §9.1 sketches `IconProvider.coverage(): List<IconCoverageEntry>`; it takes
   the apps and the theme's `IconStyle` (`coverage(apps, style)`), because the provider knows neither the list nor the
   theme. The Icons page reads the style from the resolved theme in composition (`iconStyleOf`, as home does), so the
   tool and home use the same style; a theme switch while the page is open recomputes it.
4. **Same decision as the renderer.** `sources()` loads in precedence order (override drawable, pack mapping and
   drawable, glyph, system icon and its monochrome layer) and both `render` and `coverage` call it. Coverage loads the
   drawables it needs to decide (as render does) and draws nothing. It skips private-space apps (P-5) and lists the
   other non-private apps, hidden ones included (`AppList.allApps`), so counts sum to the launchable total.
5. **Coverage rows.** App list order (collation, then hidden apps). Highlight = the theme's `highlight` colour plus a
   "Needs a glyph" text, so it is never colour alone; each row is read as "Label, Source[, Needs a glyph]". Work apps
   read "…, work". Counts list only sources with at least one app. Highlights are shown whenever icons are tinted,
   including through `pack.fallback: monochrome`; the "doesn't tint" note appears only when nothing is tinted.
6. **Export list** (owner decision, PR #27 review). Default = the highlighted (desaturated) apps, toggle "Export all
   apps". One line per app, `Label (package)`, where the label is the app's **system label**, not the user's custom
   name: the glyph author needs the real name with the package. Rows still show the custom name. Hidden apps stay
   listed and exportable (FR-SET-07: every launchable app). Through the chooser; the button is disabled when the
   list is empty. Work apps are exported with their label only (no profile). Nothing is written or kept.
7. **Glyph bundle.** The build fails on any index problem (malformed line, bad package or id, duplicate package,
   missing drawable, a drawable that is not a single-colour `<vector>` or has strokes/gradients/bitmaps/clip paths).
   Version = 16 hex chars of SHA-256 over the index bytes and the referenced glyphs' bytes sorted by id. Unreferenced
   drawables do not change the version. The id → drawable map is generated (`R.drawable.glyph_<id>`), so lookups need
   no `getIdentifier`. The index is still parsed at runtime from `res/raw` (once, lazily, off main), as §9.1 says;
   a damaged index at runtime yields no glyphs rather than a crash.
8. **Glyph drawing.** The 24-unit glyph is inset 30 % into the 108-unit adaptive layer (it fills 60 % of the visible
   72 units), tinted `SRC_IN` with the role colour on a `surface` plate and masked by the theme shape, like a
   platform monochrome layer.
9. **Production glyphs.** Only one, Strata's own (three stacked layers), so the pipeline and the checks run on real
   data. The set is authored later from the owner's exported list (roadmap: not an M8 gate). Glyphs are for personal
   use only (U-026); the index header says so.
10. **Privacy & permissions actions.** While an access is not given, the row's action runs the same flow as its
    feature switch (badge disclosure → grant page; contacts disclosure → runtime dialog; lock disclosure →
    accessibility settings), so no system grant is ever reached without the prominent disclosure. Once given, the
    action opens the system page where it is withdrawn (listener settings, App info, accessibility settings).
    "Strata has no internet access" and an "everything stays on this phone" line lead the page.
11. **`PermissionUsageActivity`** is a translucent trampoline: it reads nothing from the intent, starts
    `SettingsActivity` with the internal `ACTION_PRIVACY` (settings task) and finishes. Back on that Privacy page
    leaves settings, as for any start page.
12. **Licences.** `assets/licences.json` lists fonts (none yet: the VISUAL_SPEC §4.2 catalogue is TQ-1, open) and one
    entry per allow-listed runtime artifact family with its SPDX id and a licence text file under `assets/licences/`.
    The Apache-2.0 text is the canonical text shipped in the AndroidX artifacts; the protobuf entry carries its
    BSD-3-Clause notice. `checkLicences` requires every line of `config/dependency-allowlist.txt` to be covered, so a
    new allow-listed library cannot ship without a licence entry. Texts are read off main and only from `licences/`.
13. **About** shows `BuildConfig.VERSION_NAME`, Licences and the privacy statement. "Save diagnostic log" (ARCHITECTURE
    §11) is part 3 (with T-PRIV-06).

## Review fixes (PR #27)
1. **Coverage follows pack parsing** (MEDIUM, accepted). The view model now also combines `IconProvider.revision`, which
   the registry bumps when a pack is parsed, installed, updated or removed, so pack-mapped apps are no longer left as
   glyph/monochrome/desaturated (and highlighted, exported) after a late parse. No extra "wait for the first parse":
   pending packs already have their own revision bump, and the page updates in place when it lands. Test
   `IconCoverageTest.packParsedAfterOpen_recomputesSources`.
2. **No recompute on unrelated list emissions** (MEDIUM, accepted). The apps are projected to what the source depends
   on (key, package, labels, profile, override, `lastUpdateTime`) with `distinctUntilChanged`, so badge counts and
   other display-only changes start nothing. A recompute keeps the current rows and Export (loading shows only before
   the first result). Leaving the page sends `Hide` (`DisposableEffect`), which clears the style and cancels any load.
   Test `IconCoverageTest.badgeChangesDoNotRecompute_andHideStops`.
3. **Licence text never blank** (LOW, accepted). A missing reader or a path outside `licences/` now shows "This licence
   text couldn't be read." like a read failure. A `LICENCE_TEXT` page restored after process death (the text lives
   only in the view model) opens as the licence list. Tests `OptionalAccessViewModelTest.licenceTextNeverStaysBlank`,
   `SettingsGraphTest.licenceTextAfterProcessDeathShowsTheList`.
4. **Export labels** (LOW, owner decision): system label; hidden apps kept (choice 6). `IconCoverageEntry.systemLabel`
   added. Test `IconCoverageTest.exportUsesTheSystemLabel_andListsHiddenApps`.

## CI (mirror run 43220546655, API 26)
1. **`WidgetDeviceTest.tWidget06` timed out waiting for step 3 after two Taller taps: a product bug from M7.** Logcat
   shows home resumed, the widget placed and the resize bar shown, then no Strata error: the writes succeeded. The area
   view model computed each step from its published state (`placement.heightStep + 1`), and that state is only updated
   when the Room write flows back to main. In a cold process (it was the class's first test; "Skipped 41 frames" and JIT
   cache growth in the log) the second tap came before the first write had come back, so both stored step 2. Quick taps
   or a11y actions on a phone lose steps the same way. The new settings device tests only changed the run order and
   timing. Fix: resize steps are taken from the stored placement (`repository.current()`) under a mutex, so each tap
   counts. R test `WidgetAreaViewModelTest.quickResizeTapsEachCount_evenWhenThePublishedStateLags` (a lagging
   published flow: fails before the fix). No test change, skip or retry.

## Choices where the spec left room (Proposed)
1. **Undo snapshot and journal format.** The pre-restore snapshot is `filesDir/restore/undo.json` in an internal
   format (`"format": "strata-restore-state"`), not `undo.strata-backup.json`: the public format keys entries by profile
   kind and cannot carry user serials, `missing_since` or bound widget IDs, which an exact undo (T-BACKUP-04) needs. The
   public validator rejects it ("isn't a Strata backup"), so a user can never "restore" it from a file.
2. **Atomic Replace across Room, DataStore and theme files** (ARCHITECTURE §12.3 step 3, §10 "single Room transaction plus
   file swap"). Order: (a) the snapshot; (b) `restore/journal.json` = the target resolved for this device (the commit
   point); (c) one Room transaction for overrides + favourites + widget placements, then the exported settings fields,
   then the theme files (each AtomicFile); (d) delete the journal. A start that finds a journal writes it again before
   anything else (all-new); a death before (b) leaves all-old. A failing step writes the snapshot back the same way
   (journal = snapshot), so even a failing rollback finishes at the next start (see review fix 1). Undo uses the same path.
3. **What Replace replaces.** Overrides, favourites and the widget placement are replaced as a whole; the exported settings
   fields are set from the file (absent = catalogue default; other settings untouched); themes follow §10.4 (same id →
   Replace, others kept, active theme set when it loads). Embedded built-in ids are never written. An undo is exact: it
   also removes themes the restore added and puts the hidden-built-in flags back.
4. **Launch log.** Exported only on opt-in, as UTC day buckets of the 30-day window; never restored (the local log stays
   as it is; a restore cannot invent timestamps). It is not in the undo snapshot either (the snapshot lives in
   `filesDir`, the log only in `no_backup`).
5. **Work profile.** `work` maps to the first managed profile (lowest serial). If the phone has none, work entries are
   **skipped and counted** in the preview ("N work-profile entries skipped"), not kept pending: a pending row needs a
   user serial, and a profile created later gets a new one. Deviation from §12.1 "kept as pending".
6. **Pending favourites** (FR-BACKUP-03). A favourite of an app that is not installed gets an all-default `app_override`
   row with `missing_since` (the FR-LIFE-03 store); when the record expires the favourite goes with it. The catalog
   reconcile does the same for favourites of apps uninstalled later (consistent 30 days), and drops such a marker row
   once the app is back. Expired records are purged **before** present rows are re-activated, so an app installed after
   31 days does not get them (T-BACKUP-08). No Room migration was needed.
7. **Restored widget.** One placement (v1 has one area) with the placeholder ID −1 and `NEEDS_REBIND`. The bound ID of the
   widget it replaced is not freed (the orphan sweep skips while a placement is unbound), so Undo brings the old widget
   back; Re-add or Remove frees it as before.
8. **Fail closed** (P-5, review lesson of M6). Export maps user serials through the current profile list: main → `main`,
   work → `work` only with the opt-in; private space, `OTHER` (type unknown) and serials of gone profiles are dropped.
   Import accepts only `main`/`work`, and `work` only when `contents.workProfile` is true. Rows of the restore target only
   ever carry the main or a work serial.
9. **Hostile input.** `DocumentIO.read` caps at 8 MiB; the first non-blank byte must be `{`; `:core:json` parses with the
   §12 limits (depth 24, 4 096 items per array, 200 000 values, 4 096-unit strings, 512 keys per object — §12 sets no key
   limit; 512 leaves room for an embedded theme's 128); every value is type-checked; components, packages, drawables,
   theme ids and days match strict patterns; embedded themes are re-serialised and parsed as theme files (256 KiB and the
   theme limits); theme ids must be UUIDs before they become file names (no path traversal), and the library checks again.
   Nothing from the file is ever used as a path or an intent. Errors carry no file content. Exceptions and OOM become
   typed errors.
10. **Unknown keys** are counted everywhere outside embedded themes (top level, `contents`, `settings`, entries) and shown
    as "N newer settings will be ignored". Invalid entries are dropped and shown as "N invalid entries will be skipped".
11. **Restore detection** runs from `startCatalog()` off main and does not delay the catalog's first frame. A first start
    also has no marker, so it runs the (harmless, idempotent) post-restore steps once: a full reconcile request and the
    theme re-validation (§11.4). Widget remaps are checked by the widget area at home `onStart` as before. A restored
    `theme_index.pb` lists files that are re-parsed by `revalidateStored()` (a damaged file is quarantined even though the
    index knew it).
12. **Export self-check.** The written bytes must decode again under the import limits; otherwise "This backup is too
    large" (like the theme bundle export). With ≥ 200 large themes this is the expected outcome.
13. **UI.** The export sheet is a dialog (warning first, then the opt-ins; "Include work profile" only when a work profile
    exists). Results and errors appear as a polite live-region card on the Backup page with **Share** after an export
    (an `ACTION_SEND` of the document URI with a read grant) and **Undo restore** as a row until the next start. The picker

    ignored). Restore accepts `application/json`, `application/octet-stream`, `text/plain` (THEME_SYSTEM §3.1).

## Review fixes (PR #28)
1. **Rollback whose journal write fails** (accepted). The rollback used to skip writing the old state when rewriting the
   journal failed, and the restore's own journal then replayed the failed restore at the next start. Now the old state is
   always written; if the journal cannot become the snapshot, the restore's journal is deleted first, so the file on disk
   never describes anything but what a replay should produce. If writing the old state fails too, the error is the new
   `RestoreIncomplete` ("…couldn't be put back completely. Tap Undo restore to try again.") and Undo stays available.
   Tests `BackupServiceTest.rollback_whenTheJournalWriteFails_stillWritesTheOldState`,
   `rollback_thatFailsToo_isReportedAndRecoverable`.
2. **Private rows in `restore/`** (accepted, fail closed). The snapshot now keeps only rows of the main and work serials
   (as `profileKinds()` maps them); no private-space (or unknown-profile) serial or component reaches `undo.json` or
   `journal.json`. Undo is not exact for such rows (they are never persisted anyway, P-5). Test
   `restoreFiles_neverHoldPrivateRows`.
3. **Exact theme restore deleted themes the snapshot skipped** (accepted). `ThemeBackupData.storedIds` lists every stored
   theme the index knows; an exact restore (undo, rollback) deletes only stored themes in neither the target nor those ids,
   i.e. the ones the restore added. Unreadable files, id mismatches and failed validations stay. The journal format gains
   `themes.knownIds`. Tests `ThemeBackupLibraryTest.exactRestore_keepsStoredThemesTheSnapshotSkipped`,
   `BackupServiceTest.undo_keepsThemesTheSnapshotCouldNotRead`.
4. **Concurrent edits** (documentation). Undo is not isolated from edits made outside the backup mutex while a restore is
   active (e.g. a rename on home between Replace and Undo is overwritten by Undo). Accepted for a settings-screen flow.
5. **`missing_since` for unloaded profiles** (accepted). Like the catalog's own marking (only `loadedSerials`), the restore
   stamps `missing_since` (and pending-favourite markers) only for profiles whose apps are loaded: an available profile
   with at least one app in the catalog. A paused work profile's entries stay active; the reconcile marks them once it is
   loaded. The preview's "not installed" list follows the same rule. Test `pausedWorkProfile_entriesAreNotMarkedMissing`.
6. **Damaged or oversize journal** (accepted). It is discarded, but `undo.json` is kept on that start and "Undo restore"
   is offered (the state may be mixed). Same when a replay fails. `RestoreFileStore.exists()` tells an oversize journal
   from a missing one. Test `damagedJournal_keepsTheUndoSnapshot` (damaged and 64 MiB + 1 cases).
7. **Several work profiles** (documentation). All export as `work`; on import the duplicates are dropped (counted). Accepted:
   only one work profile is supported.
8. **Fuzz wall-clock budget** (accepted). `BackupFuzzTest` no longer asserts ≤ 200 ms per file (an invented budget on CI
   hardware); the parser limits and the 10 000 iterations stay.
9. **Vacuous private-space device checks** (accepted). `BackupDeviceTest.tBackup01` and `tPriv04` run every non-private
   assertion unconditionally, then `assumeTrue` an unlocked private space with apps: without one the run reports the
   private half as skipped, not passed. Seeding a private-serial row is not possible (the repositories refuse PRIVATE
   writes, by design).
10. **Device-test cleanup** (accepted). `@After` asserts that the undo succeeded and always puts back a full snapshot taken
    in `@Before`: overrides, favourites, the widget placement, the theme library (exact, through `ThemeBackupStore`) and the
    settings, so a failed undo cannot leave the phone with a replaced setup.
11. **Kill tests** (accepted). `RestoreKillTest` also kills at random writes of the rollback (a step failure first) and of
    "Undo restore", and checks that a failed undo is finished by the next start. All-old or all-new every time.
12. **API 26 crash in `suggestedFileName`** (mirror CI, GMD API 26, `BackupDeviceTest.tBackup01_exportContent`: a product
    bug). `LocalDate.ofInstant` is Java 9 and exists on Android only from API 31 (`NoSuchMethodError`); lint does not
    check pure JVM modules. Now `Instant.atZone(zone).toLocalDate()`. A grep of `:backup`, `:core:*` and `:testing:*` main
    code found no other post-Java-8 JDK call (`toList`, `isBlank`, `repeat` there are Kotlin stdlib). **Guard:** the
    `strata.jvm.library` convention now compiles main code with `jvmTarget 1.8`, `-Xjdk-release=1.8` and javac
    `release 8` (all but `:lint-rules`, which runs inside lint on the build JDK), so a newer JDK API is a compile error
    (checked: `LocalDate.ofInstant` → "Unresolved reference"). Tests
    keep the full JDK. Java 8 is close to, not identical with, the API 26 surface; the GMD API 26 run stays the backstop.

## Choices where the spec left room (Proposed)
1. **Focus ring.** A 2 dp `accent` stroke inside the element's bounds, 8 dp corners (pill/circle for buttons, chips and
   toggles). Applied explicitly (`focusRing()` before each `clickable`), not through `LocalIndication`: Compose creates
   a default indication lazily on the first focus, so an indication-based ring missed that focus event. Material
   controls are wrapped in `:core:ui` with the same names, so screens only swap an import. Text fields keep Material's
   focused outline, which is `accent` too (the scheme maps `primary` to `accent`).
2. **Tab on home.** INTERACTION_SPEC §5 "Tab → open S-LIST / move focus": Tab opens the list while nothing on home has
   focus; once focus is on home (arrow keys, or the window's first focus with a hardware keyboard), Tab moves between
   clock, date, favourites, "All apps", the pill and its menu. Esc acts as Back through the platform's key map
   (Generic.kcm `ESCAPE` → `BACK`); the list also handles Esc itself as before.
3. **Large text.** Font scaling stays on everywhere. Two fixed-size elements cap their glyph instead of overflowing:
   the alphabet index (pitch 14–28 dp, VISUAL_SPEC §9.3; the letter grid is the large-text alternative) and the
   monogram tile (the label beside it carries the text). Dialog bodies scroll; the search pill grows and its hint may
   take two lines; the theme editor's actions scroll sideways under the title. The editor preview is a fixed-size
   miniature of home and is not checked (home itself is).
4. **Touch targets without the Accessibility Test Framework.** The checks use Compose semantics (`touchBoundsInRoot`,
   which includes Material's minimum-touch padding, and the node size) on native graphics, which is the ATF
   touch-target rule; adding `ui-test-junit4-accessibility` (spec-allowed, test only) was not needed. Material buttons
   and chips are laid out 48 dp tall (their 40/32 dp visuals relied on invisible padding the semantics did not report
   for chips). Index letters: 48 dp wide (the strip) × their pitch.
5. **Translations.** German is the first v1 locale after English (complete; needed for T-SET-05). `locales_config.xml`
   and `localeFilters` list exactly en and de, as PRODUCT_SPEC §5 asks; the other v1 locales (es, fr, pt-BR, sv, ru, ja,
   zh-CN, ar, he) are added with their translations later. Owner: please review the German wording (or have it
   reviewed) before relying on it.
6. **Plurals before ru/ar/ja exist.** Every count string is a `<plurals>` (three plain strings converted: hidden apps
   in the list end row and the theme library, the onboarding favourites limit). With a ru/ar/ja system language the
   English text is shown with the platform choosing the form by that language's rules; the English `one` item is then
   used for e.g. 21 in Russian ("21 notification"). This goes away when those translations land.
7. **Per-app language below API 33.** There is no system per-app language before 33 and no in-app picker (none in the
   spec, and AppCompat is not a dependency): Strata follows the system language there and the About -> Language row is
   hidden. On 33+ the row opens the system page for Strata.
8. **Clock.** The digits come from the locale's best pattern for `Hm`/`hm` (+`s`), so the separator, the digits (Arabic-
   Indic in ar) and the position of AM/PM (before the time in ja) follow the locale; the theme's 12/24 h choice or the
   system setting picks the skeleton. The spoken time is the same string (it used the system 12/24 setting even when
   the theme forced the other). `words` still falls back to `numeric`.
9. **Diagnostic log.** Release builds redact at write time: messages pass `LogRedaction.message` (dotted names that are
   not platform or Strata classes become `<id:xxxxxx>`), throwables keep class names and frames but no messages. The
   export redacts again, whatever wrote the file (a debug build logs package names, ARCHITECTURE §11), and reduces any
   line that is neither a log line nor a stack frame to the thrown class. Header: version, build type, API level,
   creation time (UTC); no device or install id. Preview in a dialog (first 20 000 characters), then
   `ACTION_CREATE_DOCUMENT` `text/plain` named `strata-diagnostic-<UTC date-time>.txt`; nothing is kept. Labels, queries
   and contact data cannot be recognised in free text, so they must never reach the logger (audited: no call site logs
   them; private-space failures are not logged with their component).
10. **T-REL-03 in `:core:data`.** Like T-THEME-45, the writer is a service of the self-instrumenting `:core:data`
    test APK in its own process, so the production store classes are killed for real and nothing is added to the app
    manifest. The test does not run in the GMD job (only `:app` device tests do); it runs on the A56. Cycles default
    to 1 000 (TEST_PLAN), `cycles=N` shortens a run.
11. **Pseudo-locales.** `isPseudoLocalesEnabled` in debug builds only; en-XA and ar-XB are in `localeFilters` so they
    survive filtering (release builds generate no resources for them).
