# M8 implementation notes (part 1: settings graph, icon coverage, glyphs)

ROADMAP M8 is split. **Part 1** (this note) is the settings graph and the icon work: the root groups in the FR-SET-01
order, Themes and Icons groups, Privacy & permissions with `PermissionUsageActivity`, About and Licences with the
`checkLicences` gate, the Strata glyph bundle and source precedence (FR-THEME-35), and the icon coverage tool
(FR-SET-07). **Part 2** is backup/restore (`:backup` codec, `spec/backup.schema.json`, export/preview/replace/undo,
pending entries, Auto Backup rules and restore detection, the Backup settings group). **Part 3** is the
accessibility and i18n hardening (keyboard/switch, reduced motion, touch targets, pseudo-locales, RTL, plurals,
date/time, per-app language strings) plus the diagnostic log export. Everything is `Proposed` where `spec/` left room.

## Choices where the spec left room (Proposed)
1. **Split.** Part 1 = settings graph + icons; part 2 = backup/restore; part 3 = a11y/i18n hardening and the
   diagnostic log export.
2. **Root groups.** "Default home" and "Uninstall Strata" (FR-SET-02) lead the **Home** group (T-SET-02 lists no
   separate group for them). The old "Privacy" group is now **Privacy & permissions**: a "Permissions and access" row
   (the FR-SET-03 page) plus the app-history controls. **Themes** has one row (the theme library); **About** one row
   (version in the summary). Backup is added in part 2 between Apps and Privacy & permissions.
3. **`coverage` signature.** ARCHITECTURE §9.1 sketches `IconProvider.coverage(): List<IconCoverageEntry>`; it takes
   the apps and the theme's `IconStyle` (`coverage(apps, style)`), because the provider knows neither the list nor the
   theme. The Icons page reads the style from the resolved theme in composition (`iconStyleOf`, as home does), so the
   tool and home use the same style; a theme switch while the page is open recomputes it.
4. **Same decision as the renderer.** `sources()` loads in precedence order (override drawable, pack mapping and
   drawable, glyph, system icon and its monochrome layer) and both `render` and `coverage` call it. Coverage loads the
   drawables it needs to decide (as render does) and draws nothing. It skips private-space apps (P-5) and lists the
   other non-private apps, hidden ones included (`AppList.allApps`), so counts sum to the launchable total.
5. **Coverage rows.** App list order (collation, then hidden apps). Highlight = the theme's `highlight` colour plus a
   "Needs a glyph" text, so it is never colour alone; each row is read as "Label, Source[, Needs a glyph]". Work apps
   read "…, work". Counts list only sources with at least one app. Highlights are shown whenever icons are tinted,
   including through `pack.fallback: monochrome`; the "doesn't tint" note appears only when nothing is tinted.
6. **Export list.** Default = the highlighted (desaturated) apps, toggle "Export all apps". One line per app,
   `Label (package)`, through the chooser; the button is disabled when the list is empty. Work apps are exported with
   their label only (no profile). Nothing is written or kept.
7. **Glyph bundle.** The build fails on any index problem (malformed line, bad package or id, duplicate package,
   missing drawable, a drawable that is not a single-colour `<vector>` or has strokes/gradients/bitmaps/clip paths).
   Version = 16 hex chars of SHA-256 over the index bytes and the referenced glyphs' bytes sorted by id. Unreferenced
   drawables do not change the version. The id → drawable map is generated (`R.drawable.glyph_<id>`), so lookups need
   no `getIdentifier`. The index is still parsed at runtime from `res/raw` (once, lazily, off main), as §9.1 says;
   a damaged index at runtime yields no glyphs rather than a crash.
8. **Glyph drawing.** The 24-unit glyph is inset 30 % into the 108-unit adaptive layer (it fills 60 % of the visible
   72 units), tinted `SRC_IN` with the role colour on a `surface` plate and masked by the theme shape, like a
   platform monochrome layer.
9. **Production glyphs.** Only one, Strata's own (three stacked layers), so the pipeline and the checks run on real
   data. The set is authored later from the owner's exported list (roadmap: not an M8 gate). Glyphs are for personal
   use only (U-026); the index header says so.
10. **Privacy & permissions actions.** While an access is not given, the row's action runs the same flow as its
    feature switch (badge disclosure → grant page; contacts disclosure → runtime dialog; lock disclosure →
    accessibility settings), so no system grant is ever reached without the prominent disclosure. Once given, the
    action opens the system page where it is withdrawn (listener settings, App info, accessibility settings).
    "Strata has no internet access" and an "everything stays on this phone" line lead the page.
11. **`PermissionUsageActivity`** is a translucent trampoline: it reads nothing from the intent, starts
    `SettingsActivity` with the internal `ACTION_PRIVACY` (settings task) and finishes. Back on that Privacy page
    leaves settings, as for any start page.
12. **Licences.** `assets/licences.json` lists fonts (none yet: the VISUAL_SPEC §4.2 catalogue is TQ-1, open) and one
    entry per allow-listed runtime artifact family with its SPDX id and a licence text file under `assets/licences/`.
    The Apache-2.0 text is the canonical text shipped in the AndroidX artifacts; the protobuf entry carries its
    BSD-3-Clause notice. `checkLicences` requires every line of `config/dependency-allowlist.txt` to be covered, so a
    new allow-listed library cannot ship without a licence entry. Texts are read off main and only from `licences/`.
13. **About** shows `BuildConfig.VERSION_NAME`, Licences and the privacy statement. "Save diagnostic log" (ARCHITECTURE
    §11) is part 3 (with T-PRIV-06).

## Permissions, dependencies, manifest
- **No new `uses-permission`, no new dependency.** `checkPermissions` and `checkDependencies` unchanged.
- **Manifest (flagged):** new `.settings.PermissionUsageActivity`: `exported="true"`, guarded by
  `android:permission="android.permission.START_VIEW_PERMISSION_USAGE"` with the `VIEW_PERMISSION_USAGE` filter, as
  ANDROID_PLATFORM §22. Beyond the §22 snippet it is `noHistory`, `excludeFromRecents`, in the settings task affinity
  and translucent (it shows nothing itself). `START_VIEW_PERMISSION_USAGE` is a guard, not a requested permission.
- `assets/licences.json` and `assets/licences/*.txt` are merged into the APK from `:feature:settings`.
