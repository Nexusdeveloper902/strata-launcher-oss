# M7 implementation notes (part 1: notification badges, contact search)

ROADMAP M7 is split. **Part 1** (this note) covers notification badges (FR-NOTIF-01…03, NFR-PRIV-04) and contact
search (FR-SEARCH-06, NFR-PERF-03 contacts part). **Part 2** covers widgets: `WidgetHostController`, the picker with
previews, bind/consent/configure, the header slot with replace-clock, resize steps, remove, placeholders, the
`APPWIDGET_HOST_RESTORED` receiver and remap, safe mode suppressing widgets (FR-WIDGET-01…04, T-WIDGET-01…09,
T-GEST-02). Everything here is `Proposed` where `spec/` left room; change it with a decision if needed.

## Choices where the spec left room (Proposed)
1. **Split.** Part 1 = badges + contacts (the opt-in privacy features); part 2 = widgets.
2. **Count filter.** A notification counts when it is not ongoing (`FLAG_ONGOING_EVENT` / `FLAG_FOREGROUND_SERVICE`), not a
   group summary, its ranking importance is ≥ DEFAULT (or unknown) and `canShowBadge()` is true (the user's per-channel
   badge switch is honoured). Each notification counts 1 (`Notification.number` is ignored). The manifest filter types
   do the same on API 31+.
3. **Badge key** is (package, profile serial). A package with several launcher activities shows the count on each.
4. **Badges off** drops the counts and asks the system to unbind the listener (`requestUnbind`), so nothing is received
   while the user does not want badges; turning them on again rebinds. A listener the system binds at boot waits for
   the setting before it reads anything.
5. **Switch state.** "Show badges" is on only while setting 13 is on *and* access is granted. A revoke keeps setting 13,
   shows "Not allowed" with [Open settings], and badges come back when access returns. J-09's "Allow restricted
   settings" step is explained in the disclosure and under "Not allowed" on API 33+, with an [Open App info] row.
6. **Threading.** Listener callbacks (main) enqueue; one worker (`IO.limitedParallelism(1)`) owns the facts, resolves
   user serials (cached), calls `getActiveNotifications`/`getCurrentRanking`, and publishes on main.
7. **Contacts disclosure.** S-DISC lists contacts, so a short disclosure precedes the runtime dialog. The result of the
   dialog is checked against `checkSelfPermission` before the setting is written.
8. **Contacts query.** `CONTENT_FILTER_URI` with `LIMIT 5` in the provider's relevance order; personal profile only;
   names and thumbnails are held only for the current query. Rows show a monogram without a photo.
9. **Contacts in the keyboard selection.** Up/Down continues from the apps into the contacts; Enter opens a selected
   contact, and with no app match the first contact.
10. **Hint.** Shown when contacts are off, the query has no app match and "looks like a name" (≥ 2 letters; only
    letters, spaces, `'`, `-`, `.`). The first showing sets field 16; it then stays for that search session only. A tap
    closes search and opens Settings.
11. **Revocation of `READ_CONTACTS`** is not done by Strata when the switch is turned off (the user can revoke it in
    App info); the feature simply stops querying.

## Permissions, dependencies, manifest
- **No new `uses-permission`.** `READ_CONTACTS` was already declared (ANDROID_PLATFORM §23, *Optional runtime*); M7 starts
  requesting it, only after the user turns contact search on and accepts the disclosure.
- **Notification-listener access** (special access, ANDROID_PLATFORM §23 *Optional*): user grant in the system settings
  after the in-app disclosure. Nothing is requested at first run (T-NOTIF-01).
- **Manifest:** new `.badges.BadgeListenerService` exactly as §22 (`exported="false"`,
  `permission="android.permission.BIND_NOTIFICATION_LISTENER_SERVICE"`, the listener action, filter-type metadata).
  `BIND_NOTIFICATION_LISTENER_SERVICE` is a service guard, not a requested permission. New string `badge_service_label`.
- **Dependencies:** `:platform:notifications` uses `androidx.core:core-ktx` (already on the allow-list). `:app` depends on
  `:platform:notifications`.
- **Test APK only** (never Strata): `POST_NOTIFICATIONS`, `WRITE_CONTACTS`, `READ_CONTACTS` and the exported
  `AccessFixtureReceiver`.

## Manual checks on the Galaxy A56
- Settings › Notifications › Show badges: disclosure → Continue → One UI's notification-access page for "Strata
  notification badges" → allow → back: switch on. (Sideloaded on Android 13+: if One UI says "Restricted setting", App
  info › ⋮ › Allow restricted settings, then again.) Get a message from another app: a dot on its row and favourite
  within 2 s; Number style shows the count; an ongoing (music, navigation) notification adds nothing.
- Deny on the access page → back: switch off, "Not allowed", [Open settings] opens the page again.
- Revoke in One UI Settings › Notifications › Device and app notifications: back to home: badges gone; the settings row
  shows "Not allowed".
- Settings › Search › Contacts in search: disclosure → Continue → the Android permission dialog → Allow: search "ann"
  lists ≤ 5 contacts with photos under "Contacts"; tap opens Samsung Contacts. Deny → switch off, "Permission needed".
- With contacts off, search a name with no app match: the hint appears once; never again in later sessions.
- Leave the phone with the screen off for an hour with badges on, then `adb shell dumpsys batterystats app.strata.launcher`
  (T-PERF-09: no wakelocks, jobs or alarms).
- Run `OptionalAccessDeviceTest`: `./gradlew :app:connectedDebugAndroidTest
  -Pandroid.testInstrumentationRunnerArguments.class=app.strata.launcher.badges.OptionalAccessDeviceTest`.
  Note: tSearch13 leaves `READ_CONTACTS` granted (revoking kills the test process) with the setting off.
